T-713 - A running notebook cell has a Stop button that ends the run (DT-C149; UX audit lane C)
Worker 49, coordinator 57, branch s-49/ux-12 from main 8c9536aa, 2026-11-03.
Row: proof/ux-audit/requests/W3.md, "T-713 / DT-C149". Finding: proof/ux-audit/findings/editor-b.md F7 ("no Stop for running cell").

WHAT WAS WRONG
- A code cell's Run button showed "Running..." and was disabled until the run ended. Nothing could end a run early: a cell
  that hung waited out the 60 s ceiling, and no other cell could run meanwhile. Rust had no stop command.

THE FIX (DT-C149)
- src-tauri/src/notebook_run.rs: a STOP flag and a `notebook_stop` command that sets it only while a cell runs; the flag is
  cleared when a run starts. Setup carries the flag into run_python, whose wait loop (every 10 ms, as for the ceiling) ends
  the program and its tree the same way the ceiling does. A stopped run keeps what it printed and gets the error output
  "The cell was stopped." (told apart from the ceiling's message).
- src-tauri/src/lib.rs: the command is registered.
- src/editor/NotebookView.tsx: RunButton, one element that is Run, or Stop on the running cell (focus stays on it); the
  other cells' Run stays disabled while one runs. Stop invokes notebook_stop; the run then returns as usual and the outputs
  go into the notebook.
