WHY THE BLOCKER WAS STALE
PLAN.md T-124-d said the glyphs were "in neither the spec nor public docs". Gemini CLI's public
settings reference (geminicli.com/docs/cli/settings, the `ui.dynamicWindowTitle` entry, read on
2026-11-01, PROVENANCE.md) documents them: "Update the terminal window title with current status
icons (Ready: ◇, Action Required: ✋, Working: ✦)", on by default. Behaviour only; no Gemini CLI
code was opened. Nothing is guessed: the three icons and their meanings are exactly the page's.

WHAT CHANGED
1. src/terminal/status.ts titleState: after the Claude done star and the spinner marks, and before
   the word rules, ✋ (U+270B) reads permission (Needs you), ✦ (U+2726) reads working and ◇ (U+25C7)
   reads done, so the task text after a Gemini icon never changes the reading (same rule as the
   Claude star, T-124-c). The permission words now include "action required". Paths still say
   nothing: the path test runs first.
2. src/status/titleOwner.ts: a MARKERS row credits a leading ◇, ✋ or ✦ (followed by a space or the
   end) to gemini; a Gemini icon with another agent's name, or another agent's mark with the Gemini
   name, is a conflict (unknown), as the card asks. The three icons join LEADING_GLYPHS so the name
   after one is still read ("✋ Claude Code" is seen as the conflict it is). A NAMES row knows
   "Gemini" / "Gemini CLI" as the title's first words or last part, like the other catalogue agents.
3. docs/guide/board-agents-inbox.md: the "title stands in" paragraph names the Gemini icons and
   the "action required" words.
4. PROVENANCE.md: the dated public-doc line. PLAN.md: the T-124-d line carries the BUILT note and
   stays unticked (the live box is open).
