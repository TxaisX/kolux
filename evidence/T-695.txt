G2 [wrong?] "Open file in" select does not change value. BY DESIGN.
- src/settings/ShortcutsPage.tsx: <select aria-label="Open file in" value="">. It is an action menu.
  - Choosing an app opens the shortcuts file in that app (openShortcutsFileIn).
  - The select goes back to its prompt "Open file in..." so the same app can be chosen again.
  - A value that "does not change" is the intended state.
- The action is covered by src/settings/shortcutsFileOpen.test.ts: "choosing an app sends its command with the open request".

G4 [wrong?] Settings terminal page "Terminal input" takes no typing. BY DESIGN.
- src/settings/TerminalPage.tsx builds the terminal preview with new Terminal({ ..., disableStdin: true }).
- "Terminal input" is xterm's own label for its hidden input (@xterm/xterm 6.0.0 lib/xterm.js: promptLabel "Terminal input").
- xterm sets this.textarea.readOnly = rawOptions.disableStdin on create, so the field is read-only on purpose.
- Follow-up, not done: xterm also sets that textarea's tabIndex to 0, so Tab can still land in the read-only
  preview. Setting tabindex -1 on it is one line; this is noted in DT-C131 as overrulable.

G10 [verify only] Appearance theme/accent/zoom buttons change <html>. VERIFIED, harness false negative.
- Themes and accents: src/theme.ts applyAppearance(a, root = document.documentElement).
  - It sets document.documentElement.dataset.mode.
  - It sets every colour variable with root.style.setProperty on <html>.
  - The harness watched only the body, so it saw "no visible change".
- Covered by src/settings/__cards__/SET-001-005.test.ts, e.g. "SET-001 box 1: fresh profile is Classic;
  clicking Teal turns sidebar, top bar and accent teal inside the click, before any save", and SET-004-006.test.ts.
- Zoom: src/settings/zoom.ts sets the webview zoom (setZoom(factorOf(level))), not a DOM attribute, so a DOM watcher cannot see it.
  Covered by src/settings/zoom.test.ts ("steps half a level, about 9.5 %, and two steps make one whole level of 1.2").
