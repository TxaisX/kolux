T-716 - A usage alert counts as sent only once the send succeeds; a failed send is tried again (DT-C152; UX audit lane C)

Row: proof/ux-audit/requests/W3.md, "T-716 / DT-C152". Finding: proof/ux-audit/findings/usage-status.md F3 ("80/95% alert
marked fired before send; failure swallowed, never retried").

WHAT WAS WRONG
- src/usage/alerts.ts wrote the new fired record into memory before it called usage_alert_send, and dropped any error.
  Rust (usage_alerts.rs) saved the record to state.db before showing the toast. An alert whose toast failed was marked
  sent in both places, so it was never shown, not on the next reading and not after a restart.

THE FIX (DT-C152)
- src/usage/alerts.ts: when a reading has alerts due, the page holds the record empty while the send is out (so no
  reading sends the same alert twice), keeps the new record when the send resolves, and puts the old one back when it
  fails, so the next figures reading sends it again. One provider's alerts go per reading; the next goes on the next.
- src-tauri/src/usage_alerts.rs: usage_alert_send shows the toasts (and lights the tray dot) first and saves the record
  after. A save that fails after the toast showed may show it once more; a missed alert would be worse.
