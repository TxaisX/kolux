T-716 - A usage alert counts as sent only once its send succeeds; a failed send is tried again (DT-C152; UX audit lane C)
Worker 49, coordinator 57, branch s-49/ux-13 (on main ec26a0da, main 74dc239b merged in), 2026-11-03.
Row: proof/ux-audit/requests/W3.md, "T-716 / DT-C152". Finding: proof/ux-audit/findings/usage-status.md F3 ("80/95% alert
marked fired before send; failure swallowed, never retried").

WHAT WAS WRONG
- src/usage/alerts.ts wrote the new fired record into memory before it called usage_alert_send, and dropped any error.
  Rust (usage_alerts.rs) saved the record to state.db before showing the toast. An alert whose send failed was marked
  sent in both places, so it was never shown, not on the next reading and not after a restart.

THE FIX (DT-C152)
- src/usage/alerts.ts: when a reading has alerts due, the page holds the record empty while the send is out (so no
  reading sends the same alert twice), keeps the new record when the send resolves and then looks at the current
  figures again (a provider that came due meanwhile goes at once), and puts the old record back on an error, so the
  next figures reading sends it again.
- src-tauri/src/usage_alerts.rs: usage_alert_send lights the tray dot, hands the toasts to the system, then saves the
  record. A failed save is logged, not reported (reporting it would show the toast at every reading).
  usage_alerts_fired always returns an object.

WHAT IT DOES NOT COVER
- A toast the system drops after hand-off: the notification plugin returns Ok at hand-off, so it is not seen or retried.
- A failed save: the page keeps the alert as sent, so it shows once more after a restart, not at every reading.
- A batch where a later toast fails to build: the earlier toasts of that batch show again on the retry.
