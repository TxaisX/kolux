BUILT
Rust, src-tauri/src/automations/external.rs (new):
  - Probe trait (list, act) with a Fake for tests and the real CliProbe. Actions: run, pause, resume, remove, create, and edit (Hermes only; AUTO-025).
  - CliProbe spawns hermes / openclaw found on PATH (PATHEXT order, so openclaw.cmd beats the extensionless npm shim),
    15 s list limit, 30 s action limit, kill of the whole process tree on a timeout, a 2-slot gate (concurrency
    semaphore), and the probes are held back while a Kolux run is pending or dispatching (kolux_busy).
  - Results are cached (static CACHE) and re-read only by automations_external_refresh (the Refresh button, plus once when
    the page first opens in a run).
  - A timeout, a failure or a program that is not on the PATH is a "warning" row ("hermes was not found on the PATH", per
    AUTO-025); the Kolux list still returns either way. (An earlier review fix silenced the missing case; reverted.)
  - Defensive parsers hermes_jobs(&str) and openclaw_jobs(&str): unknown fields ignored, a bad record skipped, a bad file is
    an empty list plus a warning.
  - Hermes history: hermes_history(home, job_id, limit) reads only <hermes home>/cron/output/<job_id>/ (canonicalized and
    checked to stay inside), .md only, newest first, each run document split into titled sections on "## " headings
    (not inside code fences).
  - Rows carry source "hermes"|"openclaw", local true and an actions set (hermes: run, edit, delete, create, pause, resume;
    openclaw: run, delete, pause, resume). A row whose timetable is a cron line also carries `form` (the preset, time, day and
    custom line the Edit dialog opens on, from schedule::classify); a timetable that is not cron (an interval) has no form.
  - Hermes Edit: `hermes cron edit [--schedule] [--prompt] [--name] job_id` (flags checked with `hermes cron edit --help`).
    command() adds a flag only for a field named in the input; with nothing named it refuses ("there is nothing to change");
    a schedule that is not a five-field cron line Kolux can read is refused. Ids and values stay `--flag=value`, never bare.
  - Job ids are validated (plain words only) and Hermes create uses "--" before the positionals, so no id or prompt can
    become a flag or a path.
  - New commands in automations.rs, registered in lib.rs: automations_external_refresh, automation_external_act,
    automation_external_history. automations_list now appends the cached external rows.
TypeScript, src/automations:
  - model.ts: Automation gains source/jobId/local/actions/kind/warning/lastRunAt/lastStatus/running/pausedReason.
    New agentChoices, canDo, rowActions, splitWarnings, whereItRuns, hermesSchedule. An agent filter never keeps
    an external row; a result filter maps its own last status (ok -> Completed, error/failed -> Failed, none -> Never ran); external rows are not offered as an agent; last-run sort uses lastRunAt for them.
  - AutomationsPage.tsx: warning rows become notes above the table; rows and the detail say "Runs on this computer (Hermes)";
    pause/resume switch and Run now route to automation_external_act; the quick-action menu comes from rowActions, so a
    Hermes row has Edit and an OpenClaw row has none; Delete routes to the tool; Refresh asks the tools again.
  - AutomationDialog.tsx: "Runs in" Kolux/Hermes choice on a new automation. Hermes hides the time zone (the Hermes CLI has no
    zone flag), Agent, Project, Workspace and session reuse, "Starts" (event), grace and precheck; needs a five-field cron timetable
    (an RRULE is refused, Save stays off); Save calls automation_external_act create.
    Editing a Hermes job opens on Hermes with the job's real name, prompt and timetable (row.form); a cron line the presets
    cannot say opens in Custom. A timetable that is not cron shows as read-only text ("Hermes keeps this timetable") and has no
    fields. Save calls automation_external_act edit with hermesEdit(): only the fields that differ from the listed job; the
    schedule only when the timetable fields moved (scheduleChanged) and the result is a cron line. Nothing changed = the dialog
    just closes. The Work folder field is create-only.
  - model.ts: new scheduleChanged and hermesEdit (pure, tested).
