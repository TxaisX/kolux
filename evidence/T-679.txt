T-679 - Settings ask before removing, show errors, keep typed values (DT-C115; SET-036; UX audit lane E1)
Coordinator 57, branch s-57/ux-settings, base e93a23ba (origin/main), code commit 1154c030, 2026-11-02.

WHAT CHANGED
- Every Remove or Clear in Settings asks first, inline (Yes / Keep): accounts, provider usage,
  safety rules, custom terminal schemes, shortcut chords, AI recipes Clear, Open-in apps, clear
  attempts. The confirm keeps each control's own look (ResetButton className/title).
- Errors show where they happen: a failed save keeps the typed safety rule, a sign-in error shows on
  its row and clears when the row changes, the clear-attempts error is shown.
- Number boxes (auto-save delay, quiet minutes) save after the pause only when the text is a
  finished number in range (draft.ts `ready`); anything else waits and is saved, clamped, on leaving
  the field, changing page or closing the window. Typing again after a leave goes back to pause rules.
- The notification volume saves on release, not on every move.
- The feedback link points at the real repository; the settings search index covers every drawn
  section (a test checks each one) and opens the right fold.
- spec/17-settings-appearance.md SET-036: Rules gain the number-box pause line.

WHY
Static UX audit rows settings-b.md 2-10, backend-wiring.md 9, destructive.md 19: one stray click
removed an account or rule, errors vanished, and clamping on the pause turned "1" into 200 while typing.

REVIEW
Opus review B+ -> fix pass -> B+ -> second fix pass -> re-review A- -> leave-then-type race fixed
(test "typing again after a leave while its save runs goes back to pause rules").
