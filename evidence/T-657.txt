T-657 (R07-browser.3, DT-C93) — no tab or system-browser window opens from a page unless the user did something
Branch s-90/t657, worktree wt/90-t657, 2026-11-02. Approach: (a)+(b), no wry fork.

What changed
- (a) A window a page asks for opens only when the engine says the user started it. The engine's new-window word and the
  page's request are paired in either order; a request with no word, or a word with no request, opens nothing.
- (b) The app's own page script sends open-link and menu-pick requests; these now act only after the engine's navigation word
  says the user started that navigation. Redirects never count as user-started. A request a page sends on its own uses up
  nothing (no allowance, no tab).
- Links and menu picks take the per-family tab allowance only after the engine's word, so a burst of forged requests cannot
  spend it. A query field on a pick cannot turn it into a kind the allowance skips.
- The app's own scripts (the page picker, history steps, probes, `kolux eval` and the command line's scripts) run through
  the engine's quiet path, which lends the page no user gesture. A script that throws answers "null", as before.
- A tab that is not on screen opens nothing.
