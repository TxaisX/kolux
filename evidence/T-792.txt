Review fix 2026-11-08 (opus-high-review BLOCK findings 3, 4, 5)
- Finding 3, a chunk cut inside a character: History::append wrote the whole chunk raw when it was not whole
  UTF-8, so a secret in the readable part of a chunk cut mid-character reached the disk unmasked.
  Fix: diag::scrub_bytes masks every valid UTF-8 stretch and writes the invalid bytes and the cut-off tail as
  they came (nothing dropped, nothing altered beyond the mask); History::append uses it.
- Finding 4, ESC inside a word: scrub split words at whitespace only, so a coloured value swallowed the colour
  reset after it ("TOKEN=abc\x1b[0m" -> "TOKEN=[masked]", the reset gone) and a coloured name
  ("\x1b[31mTOKEN=abc") was never seen as TOKEN=. Fix: an escape sequence (ESC, 0x1b) ends a word in scrub
  (the sequence itself passes through, never masked, mask_next survives it) and ends a value in masked;
  escape_len knows a CSI sequence (ESC [ params final) and ESC + one char, a cut-short sequence is kept whole.
- Finding 5, mask work under the registry lock: the pane output handler called book_chunk -> History::append
  -> scrub while holding out_registry.lock(). Fix: the handler runs diag::scrub_bytes before the lock and
  passes the masked bytes into book_chunk(id, chunk, on_disk, is_program); History::append_masked writes
  them without further work. terminal/flood.rs (the stress harness) does the same.
