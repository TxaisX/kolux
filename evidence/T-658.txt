T-658 - The Skills page runs nothing inside WSL (OD-12, DT-C94; audit backlog row 6, R10-skills.4)
Worker 2f, branch s-2f/skills-wsl, base 277e0d8c, 2026-11-02.

WHAT CHANGED
- src-tauri/src/skills/wsl.rs is deleted. The Skills page no longer starts wsl.exe to list a
  distribution's skill folders or to check and remove a skill there (T-243-b, T-180-b retired).
- A project stored in WSL is scanned through its \\wsl.localhost\ (or \\wsl$\) path like any
  folder. Its three workspace skill folders are listed, and their names keep their letter case.
  The distribution's own home folders are no longer listed.
- Those skills cannot be deleted from Kolux. The row reads "In a project stored in WSL; delete it
  from WSL", and the app refuses such a pick as "wsl". The refusal covers every UNC spelling
  (\\wsl$\, \\wsl.localhost\, \\?\UNC\, \\.\UNC\, \??\UNC\) and also a path whose real location is
  a share (a mapped drive letter or a link): skills::in_wsl checks the text first, then the
  resolved path. A link inside a local skills folder that leads into a share is still listed but
  never planned for delete. Because the page can only judge a path by its text, such a row (a
  mapped drive, or a home link into WSL) still shows Delete, and the confirmation then shows it
  blocked with the WSL reason. Removing just a home link that points into WSL used to be allowed;
  under DT-C94 it is refused too.
- A folder that exists but cannot be opened is an error, not "not found".
