T-180-b · the rest of SKILL-022: skills inside WSL distributions can be deleted too
Lane: lane5/T-180-b · base origin/main 3af39cf3 · 2026-11-02

WHAT THE USER CAN NOW DO
When the open project lives inside a WSL distribution, the Skills page already lists that
distribution's skills (T-243-b). Delete skills now removes them as well: the confirmation asks the
distribution what is there (a folder, or a link and where it leads), and confirming runs one small
shell command inside the same distribution, under the shared skill-operation lock. A skill from
another distribution, or one that is not right under one of its eight skill folders, is refused as
"Outside Kolux's skill folders" without asking WSL anything. Removing a link removes the link only;
what it points at stays. A command that fails inside the distribution (FAIL line, an answer Kolux
cannot read, wsl.exe exiting non-zero or taking over 60 s) is "Failed; nothing was changed" with the
reason; a skill that disappeared meanwhile is skipped as no longer on disk. Windows and WSL skills
can go in one request. The Windows set-aside journal is not used for WSL items.

CODE
- src-tauri/src/skills/wsl.rs: DELETE_SCRIPT (header KOLUX-WSL-DELETE 1, then one of OUTSIDE, GONE,
  FAIL <reason>, OK <folder|link> <SKILL.md change time> <link target base64>; check changes
  nothing; delete is rm on a link, rm -rf on a folder, and the path must sit right under the root
  after ~/ becomes the distribution's home); Step (Check/Delete); Runner::delete; Real runs
  wsl.exe -d <distro> --exec sh -c DELETE_SCRIPT kolux <step> <root> <dir>, hidden, 60 s limit,
  non-zero exit = error; parse_reply reads the answer strictly.
- src-tauri/src/skills.rs: Places.wsl_roots = (distribution, skill folder) for the open project's
  distribution (its 5 home and 3 project skill folders); the module is pub(crate).
- src-tauri/src/skill_delete.rs: plan_with / run_with take the Runner (the Tauri commands pass
  wsl::Real; plan/run stay as test wrappers with wsl::Unavailable). A pick that wsl::split()s is
  matched against wsl_roots (other distribution, deeper path, not SKILL.md = outside), checked in
  the distribution (changed/gone/outside), and removed by delete_wsl under the same lock.
- src/skills/skills.ts: no change needed: canDelete already admits home/workspace rows, and the
  scan only lists WSL rows of the open project's own distribution (vitest pins this).
- DECISIONS.md DT-C66 (Txais to confirm: departs from OD-12 the way T-243-b already did).
- docs/guide/getting-started.md: the Skills section describes Delete skills and the WSL rule.
