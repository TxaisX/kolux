T-715 - A workspace's archive script runs when the workspace is removed (DT-C151; STAT-055)
Worker 90, coordinator 57, branch s-90/t715 from main 8c9536aa, merged with main ec26a0da and 74dc239b, 2026-11-03.
Row: proof/ux-audit/requests/W3.md, "T-715 / DT-C151" (backend-wiring finding: setup.rs workspace_archive was dead code).

WHAT WAS WRONG
- setup.rs had the archive runner (run_archive, kolux.yaml "archive" entry, 120 s limit) but its only entry point,
  workspace_archive, was marked dead_code: no removal path called it, so STAT-055's second Acceptance box
  ("Remove that worktree -> the archive script runs") could never pass.

THE FIX (DT-C151)
- setup.rs: run_archive takes a `trusted` check that is asked about the exact script text it read, so what was checked
  is what runs. workspace_archive is replaced by archive_on_remove(store, root, wt): SAFE-025's trust_ask with kind
  "archive"; an untrusted script, or one whose trust record cannot be read, is skipped and the removal goes on. The
  store lock is held only for the trust check, never while the script runs. A script this PC cannot start (a #! shell
  it lacks, a line cmd would misread) is skipped before the question, as FIX-2 does for setup: it runs nothing, so it
  neither asks about trust nor keeps the workspace from being deleted (the cleanup dialog, Space and a parent with
  its children have no force box).
- projects.rs: the shared remove_one (the single delete, the batch PROJ-071 and the cleanup dialog all route through it)
  stops the folder's terminals, then runs the archive script in the folder, before anything of it goes. A script that
  fails or runs past its time stops the delete with its error ("... It was not deleted."); a forced delete goes on.
  A script that ran and exited 0 may leave files in the folder (a log, a marker): the later "uncommitted changes" check
  is waived for it, since the stamp check before the script already guarded the user's own changes.
  remove_with(.., archive: bool) lets the CLI keep its behaviour.
- cli/mod.rs: `kolux worktree rm` calls remove_with(.., false): unchanged, it still warns that --run-hooks teardown
  scripts do not run yet (CLI-020 wiring is a follow-up).
- Front end (SAFE-025 asks first, as for setup): TrustPrompt.tsx askArchive(path) = trusted(path, "archive"), and a
  question that cannot be asked resolves false. Every removal caller awaits it before removing: ProjectsPanel (one
  workspace; a parent with its children), ProjectsExtras PickedBar, bulkRemove removeOne (cleanup dialog), SpaceView
  (each pick before workspace_remove_many).
