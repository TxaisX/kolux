== Reading ==
Tauri injects its IPC script (window.__TAURI_INTERNALS__ with the invoke key, window.ipc) into every child web view.
Its ACL (tauri 2.12.1 src/webview/mod.rs on_message) refuses app commands from any origin that is not "local"; remote
http and file: pages are refused (1, 2). An origin Tauri counts as local, the dev URL (3) or a registered custom-scheme
host such as kolux-artifact.localhost (4), gets every app command (~172) from inside a Browser pane. In a release build
the app origin is http://tauri.localhost on Windows and the artifact host stays reachable, so 4 is not dev-only.

== Fix (this commit) ==
browser.rs allowed(): a tab may open or navigate to http, https or about:blank only, never a *.localhost host (the app,
ipc and every custom scheme live there) and never the app's own dev origin; the same gate runs in on_navigation so a
redirect, link or script cannot get around it. The artifact protocol answers only the main web view. The address bar
refuses file: and drive paths. CSP for the main web view in tauri.conf.json (release) and as a Vite dev-server header
(dev). Tried and dropped: an all-frames init script deleting window.__TAURI_INTERNALS__ / window.ipc. Tauri runs its
own scripts before any of ours and defines both non-configurable and non-writable (descriptors read over CDP:
{"configurable":false,"writable":false}), so the objects stay; Tauri's origin check is what refuses them, and the gate
is what keeps a tab off every origin that check trusts. Tauri's IPC scripts are main-frame only (tauri 2.12.1
src/manager/webview.rs main_frame_script), so a frame inside a tab's page has no IPC object and no invoke key.
