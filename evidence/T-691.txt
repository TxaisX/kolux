T-691 - One keyboard helper for the editor's popup menus; the crash report on the shared dialog focus (DT-C127; APP-039; UX audit lane D follow-up to T-683 / T-684)
Lane D (72), branch s-72/ux-9, base 5177a5f2 (origin/main), code commits 504e99fb and c89e2f39, 2026-11-03.

WHAT CHANGED
- src/editor/menuKeys.ts is folded into src/editor/menuNav.ts and deleted. menuNav.ts keeps clampMenu and now holds wireMenuKeys,
  restoreIfLost and the useMenuKeys(open, close) -> { box, remember } hook; the old four-argument hook and menuKeyTarget are gone.
- The rows are found with [role^="menuitem"], so the Diff actions menu's checkbox rows are reached by the arrow keys.
- DiffPane.tsx (Diff actions) and Explorer.tsx (Open in) call remember(e.currentTarget) in the click that opens the menu;
  PreviewPane.tsx (Send) and ReviewNotes.tsx (note actions) only change their import.
- A menu in a hidden pane (panes stay mounted) leaves Escape and the arrows alone, so the key still reaches the terminal.
- src/recovery/CrashReportDialog.tsx: CrashPanel uses useDialogFocus (src/chrome/dialogFocus.ts) with Not now as the first focus:
  Tab stays inside, Escape closes from anywhere, focus goes back where it was. The component's own Escape listener and the
  autoFocus attribute are removed (autoFocus runs before the hook's effect, which would then remember the dialog's own button).
- spec/19-app-lifecycle.md: APP-039 Rules say Tab stays inside and focus goes back on close; a new Acceptance line points here.
- Rules changed: none reversed (DT-C127).

WHY
The UX audit's lane D left two copies of the same menu keyboard code (T-683 menuNav.ts, T-684 menuKeys.ts) that differed on
how they found the opener and which rows they took, and the crash report was the one dialog not on the shared dialog focus.

REVIEW
Opus review A- on 504e99fb, no must-fix; its two test and guard suggestions applied in c89e2f39.
