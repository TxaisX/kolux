T-682 - A viewer link opens only from the viewer's own frame during a click (DT-C118; SKILL-036; audit backlog row 4)

WHAT CHANGED
- src/artifacts/ArtifactsPage.tsx: new viewerLink(message, frame, activation). The library page opens a link the viewer asks
  for only when the request comes from its own frame and the window has an active click (a click inside the frame gives the
  window one; a page script that asks on its own, such as on load, has none). An engine that cannot report clicks opens nothing.
- src/artifacts/ArtifactsPage.test.ts: four tests for viewerLink.
- src/artifacts/__cards__/SKILL-036.test.ts box 2: a request with no click opens nothing; the clicked links still open.
- spec/15-skills-plugins-kits.md SKILL-036: the Rules say only clicked links open; a new Acceptance line points here.
- Rules changed: none reversed (DT-C118).

WHY
Audit backlog row 4 (held on the old #37 until now): a page shown in the viewer could ask Kolux to open the system browser or
mail client without the user clicking anything.
