T-682 - A viewer link opens only from the viewer's own frame during a click (DT-C118; SKILL-036; audit backlog row 4)

WHAT CHANGED
- src/artifacts/ArtifactsPage.tsx: new viewerLink(message, frame, activation). The library page opens a link the viewer asks
  for only when the request comes from its own frame, the window has an active click and focus is inside the frame (a click
  or key in the frame gives both; a page script that asks on its own, such as on load, has neither; the row click that opened
  the page is still active for a few seconds but leaves focus on the row). An engine that cannot report clicks opens nothing.
- src/artifacts/ArtifactsPage.test.ts: five tests for viewerLink.
- src/artifacts/__cards__/SKILL-036.test.ts box 2: the source and shape checks run with a click active; a request with no click, or with the row click still active
  but focus outside the frame, opens nothing; the clicked links still open. The test restores navigator in afterEach.
- spec/15-skills-plugins-kits.md SKILL-036: the Rules say only clicked links open; a new Acceptance line points here.
- Rules changed: none reversed (DT-C118).
