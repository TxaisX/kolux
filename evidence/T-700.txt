K1 notebook_run::tests::a_cell_that_sleeps_past_the_ceiling_is_killed (6 sightings, all on PRs with no Rust changes)
- Cause, from CI run 41680746283 (job 126074003506): "what it printed first is kept" failed with left: Null. The only
  output was the "was stopped" error: Python on the loaded runner had not printed within the 10 s ceiling.
- Fix: the test runs with ceilings of 5, 10, 20 and 40 s and stops at the first run in which Python printed. Every run
  must still take at least its ceiling and under ceiling + 20 s, and must end in the "was stopped" error. A run with no
  print must have that error as its only output. The ceiling that passed is printed (eprintln), so a log shows when a
  runner needed 40 s. Not a bigger single timeout: a quiet PC passes at 5 s, faster than before.
- Review (A-) follow-up: the cell writes a marker file right after its print. A run retries only when the marker is
  missing (Python had not printed); a marker with no "before" output fails at once as lost text, so the retry can
  never hide a capture bug. The pass log says whether the marker was there.

K2 git::tests::an_unattended_git_fails_fast_on_a_remote_that_wants_a_password
- Cause, from CI run 41664093769 (job 126014646375): "began.elapsed() < 30 s" failed at git.rs:1160. Git had failed
  correctly ("terminal prompts disabled" passed first) but took over 30 s on a loaded runner. The clock already
  started after the 401 server was up, so only command building and git itself were inside the span.
- Fix: the clock starts when git starts, and a watchdog fails the test (and kills git) only if git is still running
  after 90 s, as a password prompt would be: a prompt never returns. The "terminal prompts disabled" message is the
  proof that git asked nobody. 57 accepted the 90 s bar.

K3 agent_hooks script_runs fix_2 tests (CHAIN.md "script_runs fix_2"; no failing log left in the last 150 runs)
- Cause 1 (race): the script helper removed CLAUDE_CONFIG_DIR from the script's environment only if it was set at the
  moment it looked. with_claude_config in another test can set it between that look and the start, and then the
  script reports that test's folder. fix_2_s7 (config unset) checks that folder, so it fails.
- Cause 2 (load): fix_2_an_unset_or_empty_claude_config_dir_still_posts needs the post to land within curl's 1.5 s
  limit. On a loaded PC the script holds the event instead and stdout is empty. The live test next to it already had
  the retry for this; this test did not.
- Fix: the helper always clears CLAUDE_CONFIG_DIR for the script (the test's own value is added back after), and the
  unset-config test takes the live test's retry: the listener keeps accepting until a request arrives, and up to 4
  retries each start from a fresh spool.
