WHAT WAS WRONG
- In a 640 px window with the left sidebar and the right sidebar (Explorer) both open, the workspace got about 100 px.
  - The left sidebar is 289 px plus an 8 px gutter.
  - The right sidebar clamps to its 240 px minimum (chrome/RightSidebar.tsx clampWidth: it reserves 400 px for the
    workspace, but never goes under RIGHT_MIN).
  - So the New session sheet (absolute, inside .content) spilled under the right sidebar, and the tab strip text overlapped.
- The main window's minimum is 900 px (src-tauri/tauri.conf.json minWidth). 640 CSS px is reached by zooming the
  interface in (SET-019), or by the harness. A media query in CSS px covers both.

THE RULE (DT-C135)
- Under 900 CSS px the side panels take turns.
  - While the right sidebar shows, the left sidebar and its drag edge are hidden. This is one stylesheet rule:
    @media (max-width: 899px) { .body:has(> .rside:not([hidden])) > :is(.sidebar-wrap, .lside-grip) { display: none; } }
  - The top bar's sidebar toggle shows the left sidebar as hidden while it is stepped aside (aria-pressed false,
    "Show sidebar").
  - Every path that opens or toggles the left sidebar goes through one setter in the window store
    (shell/windowStore.ts setSidebarOpen -> shell/window/narrow.ts nextLeft). That covers the top bar toggle, Ctrl+B,
    the menu's sidebar.left.toggle, the palette's workspace rows, and workspace create, rename and delete. A toggle reads
    what is in view; opening the left sidebar in a narrow window while the right one is open closes the right one, so a
    create or rename row never opens inside a hidden sidebar. "Open" is the right sidebar's saved state, not only what
    is in view. The create, rename and palette rows switch to Terminals in the same step, and the toggles (top bar,
    Ctrl+B, menu) used from another screen close the saved state, so the right sidebar is closed when Terminals comes back.
    App.tsx keeps the setter's view of the right sidebar current, using the same test as its hidden attribute:
    terminals && right.open && !fullPage. TopBar reads that same value for the toggle's state.
  - Closing the right sidebar any other way brings back a left sidebar that was open: its own toggle, the Explorer's close, or
    Ctrl+Shift+E.
- Nothing overlays, so sheets and their Start button are never covered.
  - No z-index line was touched; T-698 / #134 owns those.
- At 900 px and up nothing changes.
- Known limit: a left sidebar dragged wider than its default (up to 480 px) can still leave the workspace narrow at
  any width, as before this change. For example, at 640 px with the left sidebar alone at 480, the workspace is 152 px.
  The 340 px floor holds for the default widths. This is noted in DT-C135.
- Left as is: the right sidebar's width clamp still counts a stepped-aside left sidebar (Right.tsx). In a narrow window
  that keeps the right sidebar at its 240 px minimum, which leaves the workspace more room (560 px at 800, not 400).
