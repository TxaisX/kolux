T-685 - The Artifacts page and the Ports popover work from the keyboard, and Remove asks first (DT-C121; VIEW-012, SKILL-036, VIEW-078; UX audit lane D)
Lane D (72), branch s-72/ux-5 (#102), base e93a23ba (origin/main), code commits 31ab6f1d and f75258aa, 2026-11-02.
This is the artifacts-and-ports part of the browser/artifacts/ports group; its sibling #99 (T-677 / DT-C113) covers the browser pane. Merge after #99.
Source: proof/ux-audit/findings/browser-artifacts.md (rows F4, F6, picker and loading rows) and findings/destructive.md row 4.

WHAT CHANGED
- Artifacts: the x on a row now opens an "Remove <title>?" confirm (the shared Ask dialog) that says the stored copy is
  deleted and the original file is not touched; nothing is deleted until Remove is pressed. It used to delete on one click.
- Artifacts list: each row is a plain select button with its own Remove button beside it (named "Remove <title>"), in a list
  per project, instead of a button inside a listbox option. Enter and Space select; Up/Down/Home/End move between rows
  (wrapping). After Cancel or Escape, focus goes back to the x; after Remove it goes to the next row, else the previous one,
  else the search box.
- Artifacts viewer: a failed file picker shows a toast (closing the picker without a pick stays silent); "Loading..." turns
  into "This page is taking a long time to load. It may be empty or broken." after 10 s; the frame stays hidden until it
  loads, which removes the white flash in a dark theme. The status line is mounted before its text so it is announced.
- Ports popover: Escape closes it wherever focus is; focus goes into it on open and back to the Ports button on close;
  a long list scrolls inside the popover (at most 60% of the window or 420 px high); Open and Stop are named by port
  ("Open port 5173", "Stop port 5173"); Stop reads "Stopping..." and cannot be pressed twice while it runs; a failed Stop
  shows a red "Could not stop port N: ..." note; when the row whose Stop had focus goes away, focus moves to the popover
  instead of falling to the page. When the scan hits its cut of 12 external ports the popover says "Showing the first 12
  external ports; more may be listening."
- Not done (listed, not hidden): "Open <ext>" opening the stored copy's folder (needs a new Rust field: the stored copy's
  path is not sent to the front end); the shared netstat poll (spans another PR's files); an exact "N more" external count
  (needs Rust). No Rust was touched.
- spec/05-views-navigation.md (VIEW-012, VIEW-078) and spec/15-skills-plugins-kits.md (SKILL-036): Rules and Acceptance
  match the above; Acceptance lines point here.

WHY
Static UX audit found that the x on an artifact deleted the stored copy on one click, that a button inside a listbox option
could not be reached or named properly by keyboard and screen readers, that the Ports popover ignored Escape, lost focus and
could run off the screen, that Stop could be pressed twice and its failures were shown as plain text, and that a page which
never loaded showed "Loading..." for good. Each fix is the smallest change that gives the keyboard and the second chance back.
