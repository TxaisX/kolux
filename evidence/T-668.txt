THE ISSUE
The UX audit (proof/ux-audit/findings) found the shell window going quiet or stuck in places:
toasts and notices drawn only on the Terminals screen, Open in browser landing on a screen that
cannot show the page, the sidebar toggle doing nothing off Terminals, a tab strip and tab menu the
keyboard cannot walk, a tab menu that can open outside the window, disabled close items with no
reason, a close question that does not say how many tabs go, a tab search that skips browser pages
and drops focus on close, a link question whose dismissal is saved as an answer forever, a restored
pane with lost data turning into a terminal, a failed settings read replaced by defaults that then
get saved, and one failing full-page screen blanking the whole window.

WHAT CHANGED (src/shell; row = proof/ux-audit/findings/<file>.md:<line>)
- Notices.tsx: toasts and notices draw once at window level (Content.tsx mounts it outside the
  Terminals block), so they show on every screen. shell.md:2.
- browserOpen.ts: Open in browser and Preview switch the window to Terminals, where the page opens.
  shell.md:3.
- sidebarScreens.ts + Sidebar.tsx: the project card follows the sidebar toggle on every screen

  shell.md:4.

  of the Tab order). Left/Right wrap and Home/End jump, moving focus only (manual activation);
  Enter or Space brings the focused tab forward, and then its pane takes the keyboard.
  shell.md:5, keyboard.md:2.
- Content.tsx: the 7 full-page screens sit inside an error boundary keyed on the screen, so one
  screen failing to draw does not blank the window and changing screen resets it. shell.md:6 part
  (error half; a screen whose code failed to load stays failed until Reload, lazy() keeps the
  failed load).

  next time. Reverses TERM-135 "still counts as answered" (DT-C104). shell.md:9.
