MAJOR 2 - offline save refused every redirect (Tailwind script tag, unpkg version ranges)
 Fix: reqwest Policy::custom(follow_cdn_redirect): follow only to an address cdn_url accepts (https,
 no user info, no port, listed path) on the SAME host the fetch began on, at most 5 hops; anything
 else stops and the 3xx is not a success. This round tightened a40e5c14's check from "any listed CDN"
 to "the same listed CDN host" as the review asked.

   other listed host, path outside /npm/, http, other port, 6th hop all refused)

MAJOR 3 - every OneDrive (reparse-point) file was refused as a link
 Fix: open_source reads the handle's reparse tag (GetFileInformationByHandleEx FileAttributeTagInfo).
 No tag: a normal file. Cloud-files tag (IO_REPARSE_TAG_CLOUD 0x9000001A, CLOUD_1..CLOUD_F
 0x9000_x01A): reopened without the reparse flag so the cloud filter can hydrate it, read only if the
 second handle has the same volume + file index. EVERY other tag is refused (this round tightened
 a40e5c14's "any tag that is not a name surrogate" to an allow-list): symlink 0xA000000C, junction
 0xA0000003, dedup 0x80000013, WOF 0x80000017, app-exec link 0x8000001B, OneDrive 0x80000021,
 HSM 0xC0000004, near-miss and unknown tags.
 Before (456f8cf0 + new table test only_a_cloud_placeholder_reparse_tag_is_kept_as_a_file):
   error[E0425]: cannot find function `reparse_is_cloud_file` in this scope (lib test did not compile);
   the old code refused ANY file whose FILE_ATTRIBUTE_REPARSE_POINT was set.
 After:  test artifacts::tests::only_a_cloud_placeholder_reparse_tag_is_kept_as_a_file ... ok
         test artifacts::tests::a_junction_or_symlink_on_windows_never_takes_the_scan_out_of_the_workspace ... ok
   The second is a real Windows test: a junction (mklink /J) where artifacts/ should be is never
   followed and nothing in the library; a file symlink inside artifacts/ is not listed and open_source
