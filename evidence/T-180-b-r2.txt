WHAT CHANGED FOR THE USER
- Major 1: a skill in the project's own .claude/.agents/.grok skills folder inside the WSL distribution can now be deleted. It was matched against the home root and the distribution answered OUTSIDE. The project root named whole now wins over a ~/ root that merely ends the same way.
- Major 2: a delete inside WSL that fails, times out or whose answer is unreadable may have removed part of the folder first. It is now outcome "unsure", worded 'Not confirmed: some of it may already be removed (reason)', never 'Failed; nothing was changed'.
- Minor (fixed): one WSL check that fails (wsl.exe error, garbled answer, FAIL line) no longer aborts the whole request. That skill is blocked as "unreadable" (page: 'WSL did not give a readable answer, so it was left alone; try again') and Windows picks and other WSL picks go on.
- Minor (left): links elsewhere in the distribution that point at a deleted WSL folder are not reported as dangling. Finding them needs a new scan script that reads every skill folder in the distribution; not small, belongs to a later task.
