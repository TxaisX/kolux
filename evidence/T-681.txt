T-681 - Terminals and floating windows never stop a program unasked (DT-C117; TERM-045; UX audit lane E3)
Coordinator 57, branch s-57/ux-term, base e93a23ba (origin/main), code commit 4660abc5, 2026-11-02.

WHAT CHANGED
- closing.ts: a failed busy check (no answer, an error, a tab whose program restarted) now asks,
  worded as unsure ("Kolux could not check whether a program is still running in it. Closing the
  tab may stop one."), instead of closing at once. The TERM-045 setting that turns the question off
  still turns this one off.
- Floating windows: the tab x, Ctrl/Cmd+W and closing a pane ask before stopping a live or unsure
  terminal, in the main close dialog's layout (Cancel first and focused). Ctrl/Cmd+W is held while a
  floating dialog or menu is open. A failed floating start shows its error and keeps the tab.
- The floating + offers terminal, agent, browser and note.
- PaneMenu: reachable from the keyboard, arrows and Home/End move, Close is last and styled as danger.
- Tooltips show the user's own keys; Find takes focus back when reopened.
- spec/03-terminals-panes.md TERM-045: Rules say a failed check asks, worded as unsure; both
  acceptance lines point here.

WHY
A failed check used to count as idle, so a dev server or agent could be stopped unseen exactly when
Kolux knew least. Static UX audit rows: terminal.md 2-9, destructive.md 6/7/14, keyboard.md 5, palette.md.
