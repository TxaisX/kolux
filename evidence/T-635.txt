T-635 · A project skill install runs only where the project cannot steer npm (R10-skills.2, DT-C82)
Worker 2f, 2026-11-02, branch s-2f/t635. Follow-up to T-633 (#80), scope set by coordinator 57.

WHAT THE USER GETS
- `kolux skills install|update --local` is refused, with a message saying why and what to do
  instead, when the project folder (or a parent below the user's own folder, as npm finds the
  project root from a subfolder) carries a `.npmrc` or a `skills` program in node_modules/.bin.
  Either would let the project decide what the installer runs. The user's own home .npmrc does
  not count.
- On Windows, a --local run is refused when Node is older than 22 (libuv 1.48): such a Node ignores
  the guard variable T-633 sets, so what it starts could come from the project folder. The message
  names Node.js 22. An unreadable version counts as old (refused, not unguarded).
- A computer-wide run (-g) is refused when the app cannot find its own folder, instead of running
  from whatever folder it was started in.
