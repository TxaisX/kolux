BEFORE
- A document previewed in a browser tab reads only itself until the user presses Allow folder on the chip
  (BROW-040). After that the button was gone, and only rebuilding the window (APP-015) took the allowance back.

AFTER
- While the folder is allowed, the same button reads "Stop allowing" (tooltip: stop this preview reading the
  other files in <folder>; aria-pressed shows the state). Pressing it calls browser_preview_revoke with the tab's address and
  reloads the page, so styles, scripts and images beside the document are refused again (403, as before the
  grant). The button then reads "Allow folder" again, and allowing works as before (with its open-folder check).
- browser_preview_revoke (src-tauri/src/browser_preview.rs revoke): finds the tab's preview by its token and
  clears its allowance; the page the tab shows is added to the documents opened, so a page reached by a
  link while allowed still loads after the reload. A tab not on a preview gets "the tab is not showing a preview". Registered in lib.rs;
  both names are literal invoke calls, so scripts/invoke-contract.mjs checks them: OK.
- Responses carry Cache-Control: no-store, so the reload asks again and cannot reuse a file read while allowed.
