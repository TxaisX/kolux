T-684 - Editor review notes, previews, PDF and notebook: no silent failures, asks before discarding, keyboard paths (DT-C120; EDIT-020/022/024/018/054/055/048/013, SAFE-003/004/007; UX audit lane D)
Lane D (72), branch s-72/ux-6 (PR #109, stacked on #98: merge after #98), base e93a23ba (origin/main), code commits 531fc6c3 and 6aa6e96b, 2026-11-02.

WHAT CHANGED
- ReviewNotes.tsx / reviewActions.ts: a failed Approve or Deny toasts "Kolux could not answer the agent: <reason>. Answer it in its
  terminal."; Approve and Request changes on a plan the agent has left toast that nothing was sent; the clear-all X asks first
  ("Clear all N notes? This cannot be undone.", Keep them focused, Escape keeps); one copy-ok / copy-failed pair is used by both copy
  paths and a failed copy also opens the Markdown for selecting; a send or start that throws becomes a tray note and keeps the notes.
- menuKeys.ts (new): the Send menu and the note-actions menu get Escape, arrows, Home/End, first row focused on open and focus given
  back to the opener after any close (unless focus already sits somewhere real, such as a dialog the action opened).
- NotebookView.tsx: Remove on a cell with text or saved output asks "Remove cell N?" and removes nothing if the notebook changed under
  the question; an empty cell goes at once.
- PdfView.tsx / pdfNav.ts (new): the page number in the facts bar is a box (Enter jumps, Escape cancels); page tops are one running sum.
- PreviewPane.tsx: Export cannot start twice (guard reset in finally); labels on Close and the menu.
- NoteRail.tsx: rail cards are focusable groups with a label; Enter/Space bring the note's text into view.
- NamePrompt.tsx: Enter on the Cancel button and any key during IME composition no longer save.
- SearchPick.tsx: Down from the box enters the suggestions, arrows/Home/End walk them, Escape and a click return focus to the box.
- TemplatePicker.tsx: after 400 ms with no list a "Looking for note templates..." status line shows.
- TableControls.tsx: greyed menu rows carry a tooltip saying why.
- trashUnused.ts: takes an onFail callback, else logs; its caller (src/terminal/paneActions.ts) is not part of this PR and is not yet
  passing onFail.
- editor-extras.css: undefined colour tokens replaced with defined ones; input borders and focus outlines use visible tokens.
- spec/12-editor-files.md and spec/10-plan-review-protected.md: Rules and Acceptance of EDIT-020, EDIT-022, EDIT-024, EDIT-018,
  EDIT-054, EDIT-055, EDIT-048, EDIT-013, SAFE-003, SAFE-004 and SAFE-007 say the new behaviour; the new acceptance lines point here.
- Rules changed: EDIT-024 (Remove asks first when the cell has content) and EDIT-020 (clear-all asks first); both in DT-C120,
  Txais may overrule. The rest adds notes and keyboard paths to spec rules without contradicting them.

SKIPPED
- Notebook Stop button (findings/editor-b.md row 11): no notebook stop/cancel/kill command exists in src-tauri/src or notebookRun.ts,
  so a button would do nothing. Needs a back-end command first.
- findings/visual.md row 4 outlines in styles.css and chat.css are lane A's (request written); browser.css tokens are not this PR's.
- TableControls focus management (row 19): not added, to keep the Lexical selection.

WHY
The night-of-2026-11-02 static UX audit (findings/editor-b.md rows 2-19, visual.md rows 4 and 7) found answers that failed without a
word, a stale plan press that did nothing, a one-click clear of every note and of a notebook cell, menus with no keyboard path and
undefined colour tokens. Rows are listed in proof/ux-audit/D-ux6.md.
