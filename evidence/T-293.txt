T-293 · APP-030 An update whose Windows signature does not match is stopped, with no bypass
Lane: reliability (Opus 5.5 stand-in), built 2026-10-20 from main 348a2a7e merged at c556cba9.

What is built
- src-tauri/src/resources/update_guard.rs (new, lane-owned): the decision function `decide(running,
  installer, pinned)`, the Windows signature reader `check_file` (Windows PowerShell from
  %SystemRoot%\System32, never PATH; the file path goes in an environment variable, never in the
  script text; no window), `parse_report`, `vet` (writes the downloaded bytes to a temp file, checks
  them, deletes the file; the installer is never started), and the refused-installer list
  (`refused_add`, `refused_has`, store key update.refusedInstallers, capped at 20). Each entry is
  known by the installer's SHA-256 and the feed's update signature, never by version, so a stale
  installer served under a new version number cannot block the real release. (The first build kept a
  version-keyed list under update.refusedVersions; that key is no longer read.)
- Rules: a damaged, untrusted or unreadable installer signature is always refused; a signed copy
  (or a build with KOLUX_RS_PUBLISHER pinned at build time) takes only an installer validly signed
  by the same publisher (compared by certificate subject, so a renewed certificate still updates);
  an unsigned copy (today's releases and development copies) takes an unsigned or validly signed
  installer (the minisign key already vouched for it). A "Valid" signature with no publisher, and
  a HashMismatch, are definite refusals (Verdict::Stop, remembered). An unclear answer (the tool
  failed, timed out, or reported a status that is not a definite verdict) is Verdict::Retry: that
  one download is stopped once, nothing is remembered, and the next check tries again. A copy built
  signed (KOLUX_RS_SIGNED_BUILD=1) whose own signature cannot be read updates nothing (Retry); a
  copy not built signed treats an unreadable own signature as unsigned. A running copy whose own
  signature reads as Broken refuses nothing for good: every installer gets Retry. An optional issuer pin
  (KOLUX_RS_PUBLISHER_ISSUER, `decide_pinned`) additionally requires an installer that passed the
  subject check to come from that certificate authority; unset today. There is no setting,
  variable or argument that skips it; update_mark("refusedInstallers", "") can only empty the list.
- Wiring (as it stands on main): update_download vets the bytes before keeping them as ready; a
  Stop verdict stores the installer (sha256, signature, version) in update.refusedInstallers, clears
  the pending update, writes a diagnostics line and returns "update:refused|<reason>"; a Retry
  verdict does the same except nothing is stored ("stopped once" in the diagnostics line). update_check drops an
  update whose feed signature is in the refused list (never offered again).
- Card (evidence/reliability-T-293-UpdateCenter.tsx.patch: card.ts, card.test.ts,
  UpdateCenter.tsx): the marker turns the card into "Update refused for security" with the reason,
  a next-step line, no Try again and no install button (mainAction null), status bar item
  "Update refused", ready pop-up cleared.
