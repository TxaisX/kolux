T-625 · The left sidebar footer fits at its narrowest width · lane/sidebar-responsive (PR #43) · 2026-11-02
Proved in the Linux cloud sandbox: Chromium 1243 (the Playwright build already installed under /opt/pw-browsers;
nothing was installed) drawing a static copy of the sidebar footer and one session row with the app's own
styles.css, Node 22, vitest 4.1.11. Nothing was run on Txais's PC. Written for the fresh review of PR #43 and
its two findings; the first round of the PR (019f60e5) shipped the change with no task line and no evidence.

WHAT IT FIXES
The left sidebar resizes between LEFT_MIN 220 and LEFT_MAX 480 (src/chrome/RightSidebar.tsx). Its footer holds
four 24 px icon buttons and the "Check for updates" button with its text. The footer was laid out from the
window's width, not the sidebar's, so at 220 px the update button's right edge sat past the footer's right edge
(229.6 px against 228 px in Chromium with the sandbox's fallback font) and the footer overflowed its card.

WHAT CHANGED (first round, 019f60e5, kept)
- src/styles.css: .sidebar is a size container (container-type: inline-size). Under 261 px of sidebar width
  (@container (max-width: 260px)) the footer tightens its padding and gap and .sb-foot .upd .label is hidden; the
  button keeps its icon, its title ("Check for a newer version of Kolux RS") and a new aria-label, so a screen
  reader and the hover still name it. .upd can shrink (min-width 0, overflow hidden) and its label ellipsises.
- src/projects/ProjectsPanel.tsx: the button's text is wrapped in <span class="label"> and the button carries
  aria-label="Check for updates".
- src/projects/sidebarResponsive.test.ts (new): pins the aria-label, the label span, the container query and the
  label rule in the source.

WHAT CHANGED (this round, after the fresh review)
- Review finding 1 (verified): the first round also put min-width: 0 on .sess, and the test pinned the literal
  substring 'width: 100%; min-width: 0; text-align: left;'. Every .sess row is a block child: its parents are plain
  <div key={w.path}> / <div key={p.id}> wrappers (ProjectsPanel.tsx) and .sb-list is a block with overflow-y, so
  min-width on .sess never takes part in layout; the ellipsis comes from .sess .name { flex: 1; min-width: 0;
  overflow: hidden; text-overflow: ellipsis; }, which was already on main. The no-op line is dropped and the test's
  string pin of it is removed; the test keeps the .sess .name assertion and now says why that is the one that
  matters. The probe below shows the session name clipped and ellipsised identically on main, on the pushed PR and
  on the branch now, which is what a no-op looks like in the browser.
- Review finding 2 (verified): no PLAN line, no evidence. This file; PLAN.md T-625 (section 8, product-ux lane);
  docs/guide/projects-and-worktrees.md says the button shows its icon alone at the narrowest width.
- The spec card for the resizable sidebar has no acceptance box for the footer at 220 px, so none is ticked.

Reading: on main the button overshoots the footer by 1.6 px at 220 and fits from about 222 up. With the PR the
label is gone at 220, 240 and 260 and back at 261 (the query is on the sidebar's own width, so the window's width
does not matter); the button is a 25 px icon at the narrow end. The position:fixed Help menu and its backdrop,
which HelpSheet draws inside .sb-foot, are not contained by container-type: inline-size (inline-size containment
does not make a containing block for fixed descendants), so the menu still opens at viewport coordinates and the
backdrop still covers the window. The session row's name is clipped with an ellipsis in all three runs.
Font: the sandbox has neither Inter nor Segoe UI, so the fallback sans-serif sets the 229.6 figure; on Windows the
text width differs by a few px and the fix does not depend on it (the label is hidden by the query, not measured).
