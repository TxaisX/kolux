WHAT WAS WRONG
- Two pollers each ran netstat: the Ports popover (src-tauri/src/ports.rs scan, every 2 s while open, 10 s closed) and the
  Preview button (src-tauri/src/browser_ports.rs listening, every 3 s). Two process launches for the same table.
- The projects sidebar (src/projects/ProjectsPanel.tsx showScanned and the pushed-branch read) set new objects every 5 s,
  so the whole panel re-rendered even when nothing had changed.

THE FIX (DT-C162)
- ports.rs: netstat(fresh) returns the system's table; shared() keeps the last one for 1.5 s (SHARED_FOR), dated when its
  run starts. 1.5 s is under the open popover's 2 s poll, so the popover never gets its own last table back; a Preview
  tick that lands within 1.5 s of a popover run reuses it. The lock is held across the run, so a caller waiting behind it
  reuses that table; a failed run is an error and is not kept. ports_list reads with fresh = false; ports_stop reads with
  fresh = true, so the Stop safety checks (lineage, start time) always see the system as it is now.
- browser_ports.rs: on Windows, listening() reads crate::ports::netstat(false). Elsewhere lsof is unchanged.
- USER-VISIBLE: the Preview button's read was "netstat -ano -p tcp" (IPv4 TCP only); it is now the popover's
  "netstat -ano", which also lists IPv6 and UDP. parse_netstat keeps TCP LISTENING lines only and one row per port, so a
  dev server listening only on IPv6 ([::1]) now shows on the Preview button; UDP never does.
- ProjectsPanel.tsx: unlessSame(next) keeps the previous value when the new one reads the same (JSON compare), so React
  skips the render. setWorktrees, setHiddenWts, setFresh and setPushedBy use it.
