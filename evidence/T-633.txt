T-633 · Skill install and update never start Node's runner through the current folder (R10-skills.2)
Worker 2f, 2026-11-02, branch s-2f/audit-sec-1.

WHAT THE USER GETS
- Installing or updating skills (Settings > Skills, `kolux skills install|update`) starts Node's
  package runner by the full path it was found at. A project folder that carries its own
  launcher under the runner's name can no longer stand in for it.
- A computer-wide run (-g) starts in the app's own folder, so the folder a command was typed in
  has no say. A project run (--local) stays in that project folder, because that is where it
  installs its skills; the full path and the rule below still apply there.
- On Windows the runner's own lookups (its launcher finding node) skip the current folder too
  (NoDefaultCurrentDirectoryInExePath=1 for that process).
- The shared program finder (agents::find_program, used by every agent start) no longer walks
  relative PATH entries such as "." or "bin", which name whatever folder the app started in.

WHAT CHANGED
src-tauri/src/skills/installer.rs
- launch(cmd, resolved, windows): takes the found path; refuses a path that is not a full path
  (on every system) and, on Windows, one holding interpreter syntax; the command line names the
  quoted full path instead of a bare "npx.cmd".
- run_dir(cmd, exe): the app's own folder for a -g run, through pty::service::start_dir, the
  helper `kolux open` already uses (T-595); none for a project run.
- Real::run: resolves through agents::find_program (the T-605 resolver), "Node.js is not
  installed" when nothing is found; sets the working folder and, on Windows, the variable above.
src-tauri/src/agents.rs
- walkable(): the last pass of search_dirs, now keeps full paths only.
