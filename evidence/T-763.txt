BEFORE
- Each live script that wanted a guard copied its own fetch wrapper (49's uncommitted t13 verify script, 72's own copy).
  scripts/prove harnesses launched through live-common had none: a row could open a browser, an editor or a folder,
  restart or update the app, install or register CLIs, or write the real ~/.kolux/keybindings.json (the dev app reads
  the real home, T-761).
- Tauri v2 sends backend calls by fetch to ipc.localhost; after one failed fetch it switches to postMessage for good.
  From then on a fetch wrapper sees nothing: blocked commands run for real and stand-ins report 0 calls. In the t13
  run this turned rows into false PASSes until the guard was probed.

AFTER
- scripts/evidence/app-launch.mjs exports IPC_BLOCK, IPC_GUARD_JS (the page script) and guardProbeJs (the check's
  page side). createApp takes ipcGuard (default false) and afterReload. With ipcGuard on, launch() and relaunch() arm
  the guard; when neither arming nor a reload-and-rearm works they close the app and throw "the IPC guard is not
  effective; refusing to drive an app ...".
- Block list, exact names only (checked against the commands the backend defines): open_external, open_install_page, open_notification_settings, open_in, open_path, editor_open, scm_open_pr, scm_open_with, the four reveal commands (scm, skills, session, browser download), app_restart, update_restart, update_download, graphics_restart_safe, graphics_choose, keybindings_show/write/reload, cli_register/unregister, agents_install(_many) and agent_install.
  The app registers no opener, shell or process plugin, so no plugin prefix is listed. Blocked calls get a "null"
  body with Content-Type application/json and Tauri-Response: ok, and are logged with " [BLOCKED]". plugin:event and
  plugin:log are not logged. Log capped at 400. Only http://ipc.localhost/ and ipc://localhost/ count as IPC.
- appEnv sets KOLUX_KEYBINDINGS_HOME to the scratch home: the app's own calls while it boots (keymap seeding) run
  before the guard is armed, and now reach a scratch keymap.
- app.guardOk(): one call with a unique name (v8_probe_N, no command behind it) must reach the log and no backend
  fetch may have failed since arming (window.__v10blind); the probe gives up after 3 s and takes itself out of the log.
- app.rearm(): reload (fetch IPC comes back), arm first, then afterReload (live-common: close first-run dialogs unless
  opts.keepFirstRun), then the check. Arming again on the same page reuses the page's own fetch (window.__v10orig).
- app.guarded(fn): checks before and after one row; { blind: "before" } = fn not run, { blind: "after" } = the guard
  went blind during fn. Either way the row counts NOT-TESTED.
- scripts/prove/live-common.mjs: startProve and startPlain pass ipcGuard: true and afterReload, so every harness that
  starts through them (directly or through live-claude-common) gets the guard; ctx.stop() logs "WARN the IPC guard was
  blind at the end of this run" before closing when the check fails. Smoke and stress (no ipcGuard) are unchanged;
  live-T-544.mjs (attach mode) is unchanged.
