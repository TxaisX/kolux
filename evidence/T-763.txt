T-763 / DT-C199 - one IPC guard for every live harness (worker 49, coordinator 57), s-49/t763 from main e5358347, 2026-11-03

BEFORE
- Each live script that wanted a guard copied its own fetch wrapper (49's uncommitted t13 verify script, 72's own copy).
  scripts/prove harnesses launched through live-common had none: a row could open a browser or an editor, restart
  the app, or write the real ~/.kolux/keybindings.json (the dev app reads the real home, T-761).
- Tauri v2 sends backend calls by fetch to ipc.localhost; after one failed fetch it switches to postMessage for good.
  From then on a fetch wrapper sees nothing: blocked commands run for real and stand-ins report 0 calls. In the t13
  run this turned rows into false PASSes until the guard was probed.

AFTER
- scripts/evidence/app-launch.mjs exports IPC_BLOCK and IPC_GUARD_JS (the page script). createApp takes
  ipcGuard (default false) and afterReload. With ipcGuard on, launch() and relaunch() arm the guard and throw
  "the IPC guard is not effective; refusing to drive an app ..." when neither arming nor a reload-and-rearm works.
- app.guardOk(): invokes v8_probe (no command behind it) and checks it reached the log; takes the probe back out.
- app.rearm(): reloads the page (fetch IPC comes back), runs afterReload, arms again.
- app.guarded(fn): checks before and after one row; { blind: "before" } = fn not run, { blind: "after" } = the guard
  went blind during fn. Either way the row counts NOT-TESTED.
- Block list, exact names: open_external, app_restart, keybindings_show, keybindings_write, keybindings_reload;
  prefixes: plugin:opener|, plugin:shell|, plugin:process|. Blocked calls get a "null" body with Tauri-Response: ok
  and are logged with " [BLOCKED]". plugin:event and plugin:log are not logged. Log capped at 400.
- scripts/prove/live-common.mjs: startProve and startPlain pass ipcGuard: true and afterReload = dismissFirstRun,
  so all 79 harnesses that start through them get the guard. Smoke and stress (no ipcGuard) are unchanged;
  live-T-544.mjs (attach mode) is unchanged.
