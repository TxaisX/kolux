  cmd and Unix shells are untouched. Not compiled into the app.
- pty_link.rs tests: shell() (used by t184b) starts its shell through without_profile.
- pty_service.rs t075b: the spawn request now carries "commands" (the user's shell chain built
  as the window builds it, minus the profile) instead of letting the service pick the default
  shell. The service's spawn op already accepts window-built commands (T-184-b), so no
  product hook was needed.
- Wait budgets: the first wait in each test covers the shell starting. It was a fixed 30 s;
  the repo's real-shell tests in pty.rs give a shell start 60 s ("the shell may take over 30 s
  to start on a loaded box"), so these two first waits now use 60 s. Later waits (shell
  already running) stay as they were.
