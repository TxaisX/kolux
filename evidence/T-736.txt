T-736 - The account switcher keeps its last list when the accounts fail to load (DT-C172; UX audit lane C)

Row: proof/ux-audit/requests/W3.md "T-736 / DT-C172", from backlog-sweep-49.md #21 (chrome.md:19).

WHAT WAS WRONG
- src/switcher/AccountSwitcher.tsx useAccountSwitcher read() set a provider's view to null when its invoke failed.
  AccountSwitcherView draws nothing with no groups, so one failed read made the top-bar pill vanish, and the
  palette rows and Board/Tower figures (src/shell/windowStore.ts, same hook) lost the accounts too.

THE FIX (DT-C172)
- read() runs both reads inside Promise.all: each success still sets its view; a failure leaves the last view alone.
  The hook's new 'stale' flag is true after a read where either provider failed, false after one where both loaded.
  The rejection is handled there, so none goes unhandled.
- The top-bar switcher passes "Accounts didn't load; list may be old." as the menu's alert line while stale; a pick's
  own error takes its place. If the first read ever fails there is no last list, so the pill stays hidden as before.
