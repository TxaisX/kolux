WHAT MAIN ALREADY DID
  - T-674 (c85cc5b0, 2026-11-02, before the sweep's base d552a974) shows SaveFailed ("That change could not be saved, so it
    was put back." plus the reason, as an alert) in every setup panel that saves: notifications, default agent, and the
    keep-awake and commit-writer stop cards. useSettings().save sets the change at once and, when the write is refused,
    reads the stored settings back and puts back the keys it tried to change (T-598). So the switches, selects, the
    volume slider and the radios already went back: NOT REPRODUCED for those.

FIXED (two gaps the review and the new tests found)
  - The read-back can fail too (a locked or unreadable settings file). Then nothing went back while the alert said "put
    back". useSettings.ts: the keys now go back to the last copy known to be on disk (load, broadcast, read-back), never an
    earlier save's change still waiting its turn (review should-fix: two refused saves in a row).
  - The commit writer's instructions box (an uncontrolled textarea, key={stored}) kept the refused text on screen when the
    save failed fast: React drew the change and the take-back in one pass, so the key never changed and the box never
    remounted. StepPanels.tsx: the box sets its own text back to the stored one when its save settles false.
