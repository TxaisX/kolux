ports-stop (lane5/ports-stop from origin/main 3af39cf3, 2026-11-01): the Stop safety guards of PR #42 (lane/ports), ported
onto main's Ports code. PR #42 branched 2026-10-19, had no common ancestor with main and its ports.rs was never wired into
lib.rs there (its tests never ran in CI); it is replaced by this unit. Route A of the brief: main's scan stays as it is
(netstat -ano, pane-ancestry tie, own rows first then at most 12 external, 10 s cadence with the popover closed, no per-scan
memory reads of other processes, non-Windows shows no ports and no error). Only what a Stop may end changed. No app launched
here (Linux container): on-screen behaviour is LIVE PROOF PENDING at the end. Logs in the session scratchpad
(ports-stop-logs/red.log, red-vitest.log, green-ports.log, green-vitest.log, tsc.log, win-check.log, win-clippy.log).

What the user can do now: a Stop in the Ports popover ends only the program the row showed. A process id that now belongs
to another program is refused ("process N now belongs to another program; nothing was stopped"): the start time travels
with the row, is read again in a fresh scan and once more right before the kill, and all three must agree. A port also
held by a program outside the workspace, by Kolux itself or by a system process is refused as a whole (every holder is
checked before anything is ended). A stop is licensed only by a workspace folder at least two folders deep, no home
folder (USERPROFILE, HOMEDRIVE+HOMEPATH, HOME, the terminals' home) and no parent of one, with a .git on disk, that the
project store lists or Git lists for the project whose folder holds it. After the kill Kolux waits up to 2 s for the
program to be gone and reports one still running. A port already gone, or now held by a program the user never saw,
counts as success and ends nothing. A printed address labels a port only when the terminal that printed it started the
holder (terminal A's "http://localhost:3000" never labels terminal B's server). The kept rule stays: only a program
started from a Kolux pane in the workspace gets a Stop at all (external rows have none).

Review fixes (PR #60 review, 2026-11-02). Logs in the session scratchpad ports-stop-logs/fix-*.log.

Findings and what was done
  major  src-tauri/src/ports.rs:82  "a stale parent pid can tie a stranger to a pane, and a Stop then ends it"
    Fixed. New pure guard lineage_ok(pid, shell, parents, start): walks from the program up to the pane's shell pid and
    requires, for every (child, parent) link, both start times present and parent_start <= child_start as u64 (a child
    is never older than its parent; Windows keeps a dead parent's id on its orphans and reuses ids). ports_stop runs it
    after stop_target, against the very parent table the scan tied the row with (scan now returns rows, parents and the
    terminals as (id, shell pid, folder); the row's `terminal` resolves to the shell pid), before folder_check, and
    refuses with "process N was not started from a terminal of this workspace; nothing was stopped". The scan itself is
    unchanged (the orphan is still listed; only the Stop refuses it).
  minor  src-tauri/src/procs.rs:211  "taskkill /T also follows stale parent pids"
    Fixed. New pure descendants(pid, parents, start): the children of the program, deepest first, keeping only a child
    whose start time is present and not older than its parent's (the same rule), and leaving one that fails out with
    everything under it. On Windows the Stop ends them itself with TerminateProcess on a handle opened and checked the
    same way; taskkill /T is no longer used by the Stop (procs::kill_tree keeps it for its other callers).
  minor  src-tauri/src/ports.rs:364  "the third start-time reading and the kill are two syscalls apart"
    Fixed. Windows: `Held`, a process handle opened once with PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_TERMINATE |
    PROCESS_SYNCHRONIZE and kept open across the reading, the kill and the wait (Windows never reuses a pid while a
    handle is open). The third reading comes from that handle, the program ends with TerminateProcess on it, and the wait
    is WaitForSingleObject(handle, 2000) on the process object, so a reused pid can never read as "still running". Each
    child is held the same way from its reading to its kill. Nothing of this is a new Cargo feature (Win32_System_Threading
    and Win32_Foundation were already on). A program that cannot be opened and is already gone counts as success.
  minor  src-tauri/src/ports.rs:176  "the pid-reuse guard is compiled off on macOS and Linux"
    Fixed. same_start is strict on every platform (an empty reading never agrees), so a scan that lands without start
    times (T-285) refuses every Stop instead of guessing; same_start_on and its platform switch are gone. Linux reads a
    start time already: field 22 of /proc/<pid>/stat (stat_start, counted from the command name's closing parenthesis).
    macOS stays empty with a ponytail (`ps -o lstart=`), which under the strict rule is the safe side.
  minor  evidence/ports-stop.txt:48  "test count off by one"
    Fixed above (16 incl. the 8 new) and in the PR body.
  minor  DECISIONS.md:656  "DT-C64 collides with PR #38's DT-C64"
    Left for the integrator, as the finding says: whichever merges second is renumbered to the next free DT-C (PLAN.md
    T-226 note and this file cite it by name). origin/main still ends at DT-C61; the open lane5 branches hold DT-C62 (x3)
    and DT-C63.
  minor  src-tauri/src/ports.rs:224  "known_workspace never asks Git for a worktree outside every project root"
    Left as is, per the finding's second option. The store catches every Git-listed worktree on the sidebar's next PROJ-041
    scan (5 s) and Kolux-made ones at creation; in that window a Stop is refused on the safe side ("not a workspace of a
    project Kolux knows"). Asking Git for every project on a store miss would also spawn one git per project for a folder
    under none of them, which the existing test forbids ("a folder under no project asks nothing"). DT-C67 wording kept.

Findings and what was done
  major  src-tauri/src/ports.rs:496  "children are chosen from the scan's stale parent table, so a pid reused after the
         scan is ended as a child"
    Fixed. end_program no longer takes the scan's parent table. On Windows it holds the program open first, then reads a
    fresh parent table, walks it with descendants (each child held open as its start time is read, so its pid is pinned
    from then on), then reads the table a second time while every child is still held and keeps, through the new pure
    guard confirmed(pid, order, before, after), only a child whose entry is the same in both readings and whose parent is
    itself kept (the program or a confirmed child). A child that ended between the first reading and its open, whose pid
    then went to a newcomer, differs in the second reading (the newcomer is newer than the program by construction, so the
    start-time rule alone could not tell) and is left out with everything under it. The scan's table still serves
    lineage_ok (a refusal path, never a kill). Header comment and DT-C67 updated: the residual is now a child the program
    starts after that table is read.
  minor  src-tauri/src/ports.rs:411  "the scan's start-time read opens every own holder with TERMINATE | SYNCHRONIZE"
    Fixed. Held::open(pid, access): start_time (every ports_list scan, lineage_ok, the Moved check) opens with
    PROCESS_QUERY_LIMITED_INFORMATION alone (const READ); end_program opens the program and each child with READ |
    PROCESS_TERMINATE | PROCESS_SYNCHRONIZE (const STOP). A program the Stop cannot open and that is not already gone is
    refused with its own reason, "Port N: process P could not be opened; nothing was stopped", no longer the stale text.
    The round-1 evidence line about start_time ("OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION) + GetProcessTimes") is
    true again; the rights each path uses are named here.
  minor  src-tauri/src/ports.rs:160  "a program that still runs but no longer holds the port is reported as Stopped"
    Fixed. stop_target answers Target::Moved when no holder of the port has the row's pid but a non-external row with the
    same pid and start time sits on another port; ports_stop also asks start_time(pid) live on a Gone answer (a program
    that rebound to no port at all) and answers Moved when it agrees with the row's. ports_stop now returns an Outcome
    ("stopped" | "gone" | "moved", a serde snake_case string) instead of (); the command's name and arguments are
    unchanged. The front end (ports.ts stopNote, PortsItem) shows "Stopped port N" only for "stopped", "Port N was already
    gone; nothing was stopped" for "gone" and "Port N is no longer held by that program; nothing was stopped" for "moved".
    The spec rule "stopping a port that already exited counts as success" holds: gone and moved are both Ok, only the note
    changed. docs/guide/terminals.md, DT-C67 and the PLAN.md T-226 note carry the three notes and the two-reading rule.
