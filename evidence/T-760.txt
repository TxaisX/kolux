WHAT WAS WRONG
- (a) src/scm/SourceControlPanel.tsx: a commit row in the history list answered a click only. Tab skipped it, so
  a keyboard user could not open a commit's file list.
- (b) The palette showed near-duplicate rows: Toggle Agent Dashboard beside Show Tower, a second sleeping-workspaces
  toggle, and "Reload Browser Page (second key)" beside the reload row. Checked on main 5e481cf2: all three old ids are entries in the sameAs map
  in src/keys/actions.ts, kept so old keybindings files still work, and each runs the same action as its partner.
  They are true duplicates, so none needed a label that says how it differs.

THE FIX (DT-C196)
- (a) The row has role="button", tabIndex={0} and aria-expanded (true while its file list shows). Enter or Space
  calls the same pickCommit as a click, with the default prevented so Space does not scroll the list.
  styles.css adds a focus-visible outline on .scm-commit-row.
- (b) src/keys/commands.ts commandRows skips an id that is in sameAs; the command it runs keeps its row.
  view.tower takes the keyword "dashboard". The alias ids still resolve for keybindings and stay in
  Settings > Shortcuts (shortcutRows.test.ts still expects browser.hardReload there). Mod+Shift+R still reloads;
  the palette's reload row shows the reload command's own keys. A user chord bound to an old id still runs its
  command but is not shown on the palette row (Settings > Shortcuts lists it). Show Tower takes "agent" and
  "dashboard", and the sleeping toggle takes "toggle", so the old rows' searches still find their command.
- Ctrl/Cmd+Enter (the panel's commit key) on a focused commit row commits only; it does not also open the row.
