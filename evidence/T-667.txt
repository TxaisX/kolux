THE ISSUE
The UX audit (proof/ux-audit/findings, against main e93a23b) found the confirmation dialog (chrome/Ask.tsx) let Tab
leave it, closed on Escape only while one of its own controls had focus, and left focus nowhere when it closed; the New
tab menu, the status bar's right-click menu and the right sidebar's More menu took no focus, had no arrow keys, and let
Escape through to the terminal underneath (where it interrupts an agent). Many controls showed no keyboard focus at all,
the project row's icon buttons stayed invisible when tabbed to, hidden icon buttons still showed, long menus and the
dialog ran off short windows, the dots menu was named "Menu", a failed app menu did nothing, and the bell closed the
Inbox to Terminals whatever was showing before.

WHAT CHANGED
- src/chrome/dialogFocus.ts (new): useDialogFocus / trapDialog and useMenuFocus / trapMenu. Reuses switcher/accounts.ts
  watchEscape (capture phase, stopped), shell/paletteCaps.ts restoreFocus and terminal/LinkActionMenu menuStep.
  A popup inside a hidden pane leaves every key alone; a menu leaves the keys alone while focus is outside it, closes on
  Tab, skips disabled rows, and caps its height from its own top (or bottom, when it opens upward).
- Ask.tsx uses the dialog trap; LayoutStrip, StatusBar and RightSidebar use the menu one. RightSidebar tabs: one tab
  stop, arrows / Home / End, tabpanel.
- styles.css: `:where(:focus-visible)` ring (zero specificity; off for xterm and tabindex -1; dropped where a control
  already shows focus with a border or background); `.proj .ib` shows on focus-visible; `.ib[hidden]` hides; `.menu`
  and `.ask` scroll inside the window; app icon radios show focus; the menu warn hint uses --warn.
- TopBar.tsx: "Terminal zoom" names; bell "Inbox", closes back to the screen before it; useChrome popAppMenu reports a
  failure, shown as a window notice (shell/window/TopBar.tsx passes setNotice).
Rows: 16 fixed, chrome.md:25 partly (the window close hover keeps the Windows close red; no matching token). None stale.
