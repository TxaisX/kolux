Decision: Txais 2026-11-09 "Build it, off by default" (DT-C242).

What was built
- Settings > General > "Experimental" card: "Agent sleep" switch (agentSleep; off on a fresh profile and when the key is
  missing; only a saved true is on) and "Idle minutes before sleep" (agentSleepIdleMinutes; 30; held 5..240 before it is saved
  and again on the Rust side).
- One check a minute while the switch is on (no timer at all while off; no per-pane timers): src/sleep/useAgentSleep.ts. A
  tick far past its minute (the machine slept) is skipped.
- Eligibility (src/sleep/agentSleep.ts sleepRefusal): agent pane, not asleep, resumable session id (resumeId, and not a guess
  from the session list), program running, a hook state is known, not permission/waiting/open ask, finished (done or idle), no
  background tasks, no unsent text in the message box (kept draft or one too long to keep: chat/composer.ts hasUnsent), not
  drawn in a visible window (focused or not), last state change older than the delay. Anything else: awake. The decision is
  re-made against the latest state right before the Rust call and again before anything ends (the pane, its terminal id and
  its state must all be as they were).
- Sleep: Rust `agent_pane_sleep(pane_key, idle_minutes)` (src-tauri/src/agent_sleep.rs) re-checks the switch, holds the delay
  5..240 (20 s only in a development build with the test-only key), requires the pane's terminal with the agent in front and
  nothing else (the launch record and the foreground poll's own answer: another agent, a shell or an unknown foreground
  refuses), requires the terminal to have neither printed nor been typed into for the delay (Terminals::still_for over the
  mark's started / last_output / last_input; Terminals::write stamps last_input), then records the session
  (saved::at_pane_sleep → sleep_record: the live row must be done or idle, not monitoring (status::SESSIONS), and at least
  the delay old; keyed by session like workspace sleep; a failed write is an Err and nothing ends) and answers the terminal id
  and the recorded session id. The window then marks the pane asleep (its terminal unmounts, which ends only that pane's Job
  object), drops its pty entry and running flag, waits for the commit, and ends the terminal by id. Placeholder: "Asleep to
  save memory · idle N min" + Wake (src/sleep/AsleepPane.tsx).
- Wake (useAgentSleep.wakeOnce): agent_start_line { restore: true, session: <the recorded id> } (the same call main.tsx makes
  for a restored tab), the key added to restoredKeys so the terminal remounts as a restored tab (kept output replayed); the
  resume line replaces the launch args and clears the opening prompt (`typed`), so neither runs again; the idle stamp is reset
  to now; one wake per pane at a time. A refused start keeps the pane asleep and shows a toast ("The sleeping agent did not
  wake: ..."); nothing is spawned.
- Not persisted: a sleeping pane is not saved with the layout; after a restart it comes back as a plain shell like every agent
  tab (DT-C27). Documented in TERM-123 and DT-C242; no persistence built.
- Docs: TERM-123 and HID-028 cards (state, rules, acceptance ticks with proof), DECISIONS.md DT-C242 (+ the two "skip" rows
  updated), docs/guide/settings.md "Experimental", PLAN.md T-817, STATE-history lines.

Runtime proof
- Not run. A live sleep needs an agent that reports a finished turn with a resumable session id through the hook listener
  (DT-C240 per-pane tokens). No Claude or Codex login exists in a scratch profile and the owner's credentials may not be used;
  the repo has no stand-in agent that speaks the hook protocol, and writing one plus a dev build of the app did not fit the
  lane's turn budget. The development-only `agentSleepTestFast: true` setting (20 s delay, 5 s check, on both sides; never read
  by a release build) is in place for that proof: start the dev app with a scratch profile, open an agent, let a turn finish,
  switch to another tab (the pane must be off screen), and watch the placeholder appear within about 25 s, then Wake.

Did not fit
- `resumable()` keeps only unfinished rows, but a finished turn must be sleep-eligible: at_pane_sleep records the pane's row
  without that filter (sleep_record), keyed by session id as before.
- No Experimental settings page exists in the rebuild (SET-044), so the switch lives in an "Experimental" card on General.
- The foreground poll answers per terminal with the root process first (T-050-c), so "a program other than the agent is in
  front" is only partly knowable for a program session; the quiet clock covers the rest.
