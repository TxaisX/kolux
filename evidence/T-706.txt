FIXED
  - src/lazy/deferred.tsx: deferred(load, fallback?); the fallback goes to Suspense (none draws nothing). Once a surface's module has
    loaded (prefetch() or a first open), deferred() keeps it and hands it to React's lazy() as a thenable that answers at
    once, so a screen prefetch has already read draws on its first open without suspending (no fallback frame).
    Before this, prefetch() called the raw import, which warmed the module cache but not lazy(), so the first open
    still suspended once (found by the review).
  - src/lazy/pages.tsx: one shared element, <div class="empty" role="status">Loading…</div>, inline (no new component file).
    It reuses the muted, centred empty-state style (.empty in styles.css), so there is no new CSS.
    Passed by the nine full-page screens Content.tsx draws: TasksPage, AutomationsPage, RoutingPage, SkillsPage,
    ArtifactsPage, InboxView, TowerView, FloorView, SpaceView.
  - AgentsChat keeps null: it shares the content column with the Agents grid and the Agents empty state, and chat.css
    hides those by what sits next to .chat (.chat + .empty, .chat.cover ~ .grid.agents), so a flex:1 placeholder there
    would split the column or squash the terminal grid (found by the review).
  - Everything else in pages.tsx keeps fallback null: the pane bodies (Explorer, ChecksPanel, InsightsPanel, ChooserPane...),
    the sheets and dialogs (PlanSheet, HelpSheet, UpdateCenter, FeedbackDialog...), the notices (SignInNotice,
