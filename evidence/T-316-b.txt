T-316-b piece 3 (2026-10-25, lane/browser): EDIT-018 export a note to PDF, the browser side.
BUILT
- src-tauri/src/browser_pdf.rs (registered as browser::pdf in browser.rs): browser_export_pdf(html, title, path, overwrite)
  wraps the caller's rendered HTML in a page whose policy is default-src 'none', img-src data:, font-src data:, inline style
  only (no script, no network, no remote picture), writes it to a temp file under the app temp dir, opens a hidden page on
  that file (a WebviewWindow: invisible, offscreen at -32000, no taskbar entry, only that one address may be navigated to,
  every new window refused), waits for the load, prints it with the engine's PrintToPdf (engine::print_pdf, the one the
  kolux pdf command uses) to a temp PDF, checks it starts with %PDF, and only then writes the chosen path.
  The path must be absolute, without .., end in .pdf, in a folder that exists, not a folder, and not an existing file unless
  overwrite is true; without overwrite the file is created new, so a file that appeared since the check is never replaced.
  The hidden page is closed by a drop guard (success, load timeout, print error, refused print, bad file, open failure after
  the window exists) and the temp html and pdf are removed by another. A note over 48 MB of html is refused.
- browser_pick_pdf_path(title, folder): the system save dialog (tauri-plugin-dialog from Rust: the app had no save dialog
  before, only open pickers, and the JS side has only dialog:allow-open), offers <title>.pdf, Untitled.pdf without a title.
- src/browser/notePdf.ts: noteTitle, embedPictures (every blob: picture in the html becomes a data: address; one that
  cannot be read loses its address), bytesToDataUri, exportNotePdf (pick path, embed, print with overwrite true because the
  system dialog has already asked about replacing).
- The engine code has no request blocker for this (its only WebResourceRequested filter edits client hints), so the block is
  the page's own policy plus the navigation guard; no new dependency.
- Patches: evidence/browser-fix-T-316-b-lib.rs.patch (registers both commands; apply after 719, 151, 746) and
  evidence/browser-fix-T-316-b-PreviewPane.tsx.patch (src/editor/PreviewPane.tsx, the editor lane's file: a Note actions
  menu with Export to PDF..., the on-disk pictures read in as data addresses, a status line saying where it was saved).

SECURITY RULES AND WHERE THEY LIVE (notebook_run.rs)
1. Trust is checked in Rust: run_cell_in refuses before reading the file (the "not trusted" error); the path is canonicalised and the \?\ prefix stripped in both notebook_trust and the check (real_notebook, plain, key); only an existing file ending in .ipynb counts. Trust belongs to the path: a trusted path whose file is replaced still counts as trusted (card model; test a_replaced_file_stays_trusted_by_its_path).
2. Interpreter: pick_python takes files::find_program over the PATH's absolute folders only (a relative entry such as "." is dropped), drops any folder equal to or below the notebook folder, requires an absolute result, and the program is started by its absolute path. Test the_interpreter_is_never_taken_from_the_notebooks_folder plants python.exe/python3.exe/py.exe/python.bat files in the notebook folder, in a folder below it and as "." on the PATH.
3. run_cell_in -> read_cell: bounds check and cell_type == "code", else an error before any process starts (test only_a_code_cell_at_a_real_index_runs).
4. A timeout calls procs::kill_tree (taskkill /T on Windows, a process group elsewhere) then Child::kill. ponytail: a child that detached itself first is not reached.
5. run_python removes every KOLUX_* variable and CLAUDE_CODE_OAUTH_TOKEN (claude_key::ENV) from the child, keeps PATH; no shell; the cell text goes to standard input only (tests a_cell_does_not_see_kolux_secrets, the_cell_text_goes_on_standard_input_never_on_the_command_line).
6. drain reads 8 KB chunks and keeps at most 1 MB per stream, then keeps reading and drops the rest so the program never blocks on a full pipe; stdout and stderr are read on separate threads (tests a_two_megabyte_print_is_capped, the_capture_stops_reading_at_its_cap).
7. No network code was added; scripts/privacy-audit.test.mjs passes unchanged.
8. Error strings are fixed plain sentences with the cell number only; the cell text is never in one (tests check "open(" is absent).

CHOICES TO KNOW
- python is started as: python -I -X utf8 - (the brief said -I -; -X utf8 makes the output UTF-8 whatever the Windows code page). -I also means a module next to the notebook is not importable.
- Exit 0 with text on stderr (a warning) is a stderr stream, not an error output, as Jupyter does; a non-zero exit or a timeout is an error output (ename Error, evalue the last stderr line).
- CRLF from Python's Windows text layer is turned into LF in the stored output.
- execution_count is one more than the highest the notebook already shows.
- Rust reads the file on disk, so the page saves first (notebookRun.ts calls EditorPane saveQuiet, then runs); the outputs are put into what the tab holds at the end, so typing during a run is kept.
