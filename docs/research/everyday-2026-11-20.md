# Everyday: one plain folder above the projects (2026-11-20)

My ask: "there should also be a everyday tab right above the folder so that we can go and chat with any
model about our daily asks. you can also make it into a drop down so that we can open and close the
everyday asks."

## What it is

- One plain folder at `<home>\Kolux\Everyday`, made on the first **New session**, never at start-up.
- An ordinary folder project: no Git, so nothing is committed, merged or pushed. `project_remove`
  refuses it; its files are the user's.
- Chats started there get `GIT_CEILING_DIRECTORIES` (`claude_shared::everyday_env`), so a repository
  above the folder stays invisible to git.

## The row

- Its own section above the "Folders" heading, with a hairline under it: a spark, "Everyday", a status dot
  when one of its chats has a state, and a chevron. It starts open; the chevron opens and closes the asks.
  The section sits outside the scrolling project list, so the "Folders" heading stays put; a long list of
  asks scrolls inside itself (34% of the window's height at most).
  The folder itself is never listed twice: the project list, the project headers and the grouped
  stand-ins all skip it.
- The asks are the panes opened in that folder, each with its own status dot; a click brings its pane
  forward. A Claude chat is named "New chat" until its first message, then takes that message's first
  line as its name (40 characters at most), as a chat app does.
- **New session** (2026-11-20) opens a menu of every installed AI, Claude first, each with the models it
  can start on. A Claude pick opens the chat surface on that model; every other AI opens its own session
  in the same plain folder on the picked model. Each pick is a session of its own, so more than one can
  be open at a time; "Program default" adds no `--model` flag. An AI with no model list (OpenCode, for
  one) offers one "Its own default" pick: its session starts on the program's own configured model.
- **Any AI…** stays at the foot of that menu and opens the Start form on the Everyday folder, the full
  chooser for anything the menu does not carry.

## Update: OpenClaude, the second chat engine (2026-11-20, later that day)

Txais: "we need to run openclaude so that we can run the other models then." OpenClaude is a Claude Code
fork with the same CLI (`-p --input-format stream-json --output-format stream-json --verbose`), and it adds
`--provider <gateway>`. So a chat can run it with one extra field, not a second engine.

- **The engine.** `chat_engine::Spec` carries `agent`; `chat_start` takes `agent` (absent means `claude`)
  and refuses any id but `claude`/`openclaude`. The program is found by that id (`agents::find_program`) and
  the sign-in asked by that id (`terminal::agent_env`), so an OpenClaude chat inherits the ordinary
  environment — the OpenRouter key is already there — and never a Claude account's folder.
- **Permissions.** Measured the same day, one turn each with `--permission-mode` `auto`, `acceptEdits`,
  `dontAsk`, `fullAccess`, `bypassPermissions`: only `acceptEdits`, `fullAccess` and `bypassPermissions`
  wrote the file. `auto` is not a mode OpenClaude knows; it reports `default` and refuses the tool call.
  An OpenClaude chat therefore starts with `bypassPermissions` — DT-C283's "never ask" rule under the name
  this program knows. Claude keeps `auto`.
- **Models.** OpenClaude's list is OpenRouter's ids, six of them, each one answering a live prompt that day:
  `deepseek/deepseek-v4.1-flash-1017`, `openai/gpt-5`, `openai/gpt-5-mini`,
  `google/gemini-3-flash-preview`, `anthropic/claude-opus-4.5`, `x-ai/grok-4.6`. A picked model starts with
  `--provider openrouter` (the chat engine and the terminal line, from one list in `seats.ts`); "Program
  default" adds neither and keeps OpenClaude's own setup. `--resume` works across processes, proven with a
  two-turn test, so an idle-slept chat comes back with its conversation.
- **The page.** A pane carries `chatAgent`; the chat page uses it for its title, mark, `readModel` and
  `chat_start`. The Everyday menu's chat flag is now `EVERYDAY_CHAT_AGENTS` (`claude`, `openclaude`), so an
  OpenClaude pick draws the chat page instead of a terminal. Its model is a start flag, so the composer's
  model picker saves the choice and says "Set when a session starts" rather than sending `/model`.
- **Known gap, left alone.** `chat.rs::homes` still reads OpenClaude transcripts from `~/.claude` (it reads
  the two the same way). Chat panes never read transcripts, so nothing here depends on it; a terminal
  OpenClaude's session list would look in the wrong folder.
- **Proof.** `cargo test --lib chat_engine` 14/14 (including
  `openclaude_gets_the_mode_it_knows_and_its_gateway`), `pnpm check` green, touched vitest files 94/94, and
  the live off-screen run `G:/Temp/surface-proof/shot-openclaude.mjs` (menu group, chat page, title,
  mark, model, and a real answer in a bubble).
