Lessons

1. Three local sessions on one repo, one worktree per pull request: it worked. 26 merges, no session overwrote another's files, and no merge had to be undone on main. The one accident (lesson 4) happened on a branch, and nothing on main was affected.

2. One merger, one merge at a time, was steady. The first 23 merges (#54 to #74) took 9 h 23 min, about 25 minutes each. Gaps ranged from 21 to 42 minutes, with a median of 24. Every merge re-ran CI with the newest main inside it, so no merge broke the next one.

3. Pre-assigned number blocks prevented collisions. In the cloud phase, two lanes picked the same decision numbers (DT-C62 three times, DT-C67 twice), and they were renumbered at merge to DT-C68, C69 and C70. In the local phase, each session got its own block (2f: DT-C80–C82 and T-632–T-637; 90: DT-C71), and there were zero collisions. The bookkeeping reviewer confirmed no duplicate number was added this cycle.

4. A "hands off" message arrived too late. Session 90 pushed e3dc147d to #69's branch after that branch had been handed to 2f. The commit deleted 2,680 lines, undoing the work of #72–#74 on that branch. 90 reverted it a minute later (d3bcbd57) without force-pushing, so history stayed honest and the two commits cancel out. Fix for cycle 6: every branch gets one named owner, and when work moves, the old owner's branch is locked before the new owner starts.

5. The first-load budget was hit twice. #69 went 4 bytes over after main was merged in, and then 97 bytes over after #75 landed. Both times, code that only one screen needs was moved out of the startup download, and the ceiling was not raised. The first load is now 1,483,871 bytes, 1,129 under. The margin is thin, so expect this again.

6. The artifact-frame scare was settled in a day. A review suggested that pages shown in the artifact viewer might reach the app's internal commands. A live test (three runs, with a control) could not make that happen, and the release hold was lifted the same day (#73). The underlying weakness is real but not reachable today, and hardening is filed as T-632 for cycle 6.

7. #37 was parked rather than rushed. After five review rounds, one HIGH finding is still open (finding 1). The pull request stays open for cycle 6, and the problem is described here only at issue level because the repo is public.

8. The flaky-test list shrank but did not go away. #65 started two terminal tests without a PowerShell profile, and those tests have not failed since (11 later merge heads). Four known flaky tests remain, and one of them turned main red at close. Fix for cycle 6: put each flaky test in the plan with an owner, and give the after696 test the same no-profile start.

9. You had to approve permissions in each pane yourself. Each session needed your own message ("I approve: for cycle 5 you may push branches, open/update/close PRs, comment, re-run CI and merge…") before it could act on GitHub. One session's permission settings also blocked a branch delete the coordinator wanted to make. Approvals do not carry between sessions, so a three-pane cycle needs three approvals.

10. New from grading: a review grade covers only the commits it read. Several hand-off grades had no record on the pull request, and #69's last review came before its JPEG 2000 commits. Fix for cycle 6: post every review's grade and commit on the pull request, and re-review any commit that lands after it.

11. New from grading: write follow-ups into the plan, not just into comments. Three pull requests left their review follow-ups only in comments, where cycle 6 will not see them. They are listed below.
