Kolux RS · architecture

One app, one service, four local doors.

Kolux RS runs many AI coding agents side by side on Windows. This is the runtime map: the two processes, the four loopback doors, the single profile, and the trust boundaries that keep the app's own files and update path separate from the agents it runs.

The shape in words

The window is React and TypeScript. The core is Rust and Tauri 2. A detached child process owns the PTYs, so panes can outlive a window reload or an ordinary quit. Every local door binds loopback on a random port and requires a bearer token. Worktrees are ordinary Git, and the profile is the only store.

Processes

  • Desktop: window, React UI, Rust commands, store, listeners, updater.
  • Terminal service: detached child, PTY sessions, job objects, TCP loopback.
  • WebView2: the browser engine for the window and browser tabs.
  • Agents and shells: children of the service, one pane job each.

Trust boundaries

  • App code is trusted. Browser pages are not.
  • Loopback only, but the tokens are in user-readable files. Same-user malware can read them.
  • Agents run with the user's permissions. Kolux is not a sandbox.
  • Update trust is one minisign key. A compromised key can reach every installed copy.

Update path

Check releases/latest/download/latest.json, download into memory, verify the minisign signature, check the Windows publisher, hand the children out of the kill-on-close job, then run the NSIS installer.

The installer itself is not Authenticode-signed yet. Use Restart to update; quit-to-install is not proven end to end.
